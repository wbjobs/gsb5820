# 加密协同任务看板（无服务器）

纯前端实现的多标签页实时协同看板：无服务器、端到端加密存储、离线可用、CRDT 自动合并。

## 运行

```bash
python3 -m http.server 8000   # 或任意静态服务器（Worker/模块需要 http 协议）
# 打开 http://localhost:8000 ，再复制 3 个标签页，共 4 个
```

首次打开设置主密码（派生加密密钥）；之后每个标签页用同一主密码解锁。

## 测试

```bash
node test/crdt.test.mjs   # CRDT 收敛 / 冲突 / 乱序 / 离线合并 / 3000 次操作 4 节点模拟
```

## 技术架构

| 需求 | 实现 |
| --- | --- |
| 实时同步 | `BroadcastChannel`（`js/sync.js`），同域标签页毫秒级广播 |
| 持久化 | `IndexedDB`（`js/store.js`），操作日志逐条加密存储 |
| 拖拽 | `Pointer Events`（`js/app.js`），支持鼠标/触摸，列内排序 + 跨列移动 |
| 一致性 | CRDT：HLC + 字段级 LWW + 墓碑删除 + 稠密位置键（`js/crdt.js`） |
| 加密 | `Web Crypto`：PBKDF2(25 万次, SHA-256) → AES-GCM-256（`js/crypto-worker.js`） |
| 主线程减负 | 加解密全部在 `Web Worker` 中执行，密钥不可导出、不出 Worker |

## 冲突与一致性设计

- **拖拽冲突**：两个标签页同时移动同一任务 → 按 HLC 最后写入者胜，全端确定一致。
- **排序冲突**：位置使用稠密分数键（base-62），并发插入同位置时以任务 id 决胜，顺序确定。
- **删除冲突**：删除是墓碑操作；删除与编辑并发时 HLC 大者胜（删除晚则消失，编辑晚则复活）。
- **消息乱序**：CRDT 合成本身满足交换律/幂等；另有按源序列号的重排缓冲 + 150ms 缺口修复请求（`need`/`ops`），丢消息会从 IndexedDB 补发。
- **离线合并**：所有操作先写本地 IndexedDB；标签页关闭期间其他标签的操作也在同一 IndexedDB，重开时回放合并；`hello` 反熵协议补齐缺失操作。
- **密钥错误**：解锁时用存储的 verifier 校验，错误提示"主密码错误"；同步中收到无法解密的数据（AES-GCM 认证失败）会显示横幅警告。
- **标签页关闭**：`beforeunload` 广播 `bye` + 3s 心跳 / 9s 存活超时，头部实时显示在线标签页数。

## 验收标准对照

| 标准 | 说明 |
| --- | --- |
| 4 标签页并发 5 分钟一致 | CRDT 收敛性由 `test/crdt.test.mjs` 的 3000 操作 4 节点模拟保证 |
| 离线恢复合并正确 | 操作日志共享于 IndexedDB，重开放映 + 反熵补齐（有测试覆盖） |
| 加密存储刷新可解 | 每条操作 AES-GCM 加密落盘，解锁后回放解密 |
| 密钥错误有提示 | verifier 校验失败提示；同步解密失败横幅提示 |
| 拖拽/删除冲突正确解决 | HLC LWW + 墓碑，测试覆盖 |
| 消息乱序不丢操作 | 重排缓冲 + 缺口修复 + CRDT 幂等合并，测试覆盖 |
| 同步延迟 < 200ms | BroadcastChannel 为微秒级同源广播，渲染用 rAF 合批 |
| 主线程不卡 | PBKDF2/AES-GCM 在 Worker；IndexedDB 全异步；渲染 rAF 合批 |
